# Ficha del problema _ EnAgenda

## Problema

Las personas que organizan eventos pequeños suelen manejar invitados, tareas,
horarios, elementos necesarios y gastos mediante conversaciones, notas y listas
separadas. Esta dispersión dificulta saber qué está preparado, quién confirmó su
asistencia y qué actividades siguen pendientes.

## Usuarios

El usuario principal será el propietario u organizador del evento. Los invitados
serán usuarios externos que podrán consultar la información pública y responder
mediante un enlace individual, sin crear una cuenta.

## Propuesta

EnAgenda centralizará la organización de eventos pequeños. El propietario podrá
registrar el evento, gestionar invitados, consultar respuestas, administrar
tareas, organizar la agenda, registrar elementos necesarios y llevar un control
básico del presupuesto.

## Alcance inicial

El MVP se concentrará en:

- Creación y edición de eventos.
- Registro de invitados.
- Enlaces individuales de invitación.
- Respuestas de asistencia.
- Gestión básica de tareas.
- Registro de elementos necesarios.
- Agenda básica.
- Presupuesto básico.
- Panel de seguimiento.

## Fuera del alcance

No se incluirán inicialmente pagos en línea, chat, envío automático de correos,
varios propietarios, roles de colaboradores, videollamadas ni integración con
calendarios externos.

## Tensiones preliminares

- Privacidad vs. facilidad de acceso: los invitados deben responder sin
  registrarse, pero solo pueden consultar la información que les corresponde.
- Funcionalidad vs. alcance: se busca una aplicación útil sin exceder la
  capacidad de un equipo de tres estudiantes.
- Consistencia vs. rapidez: las respuestas deben actualizarse
  correctamente sin generar duplicados ni volver lento el panel.

## Restricciones

El proyecto será desarrollado por tres estudiantes durante el calendario del
curso. Debe poder evolucionar mediante entregas semanales, utilizar datos
ficticios y llegar a un sistema funcional, probado y desplegado.

La plataforma tecnológica aún no está definida. El equipo evaluará una solución
móvil, web o híbrida y documentará la decisión posteriormente.

## Primer aspecto declarado

El primer aspecto es la gestión de invitaciones mediante enlaces individuales.
Este aspecto permite recorrer una funcionalidad desde el requisito hasta el
diseño, el código, las pruebas y la evidencia.
